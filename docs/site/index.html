Why it's one computer, not a distributed system

  • One firmware. Flash every board the same; a brain is elected at boot. A newcomer joins in seconds, mixed chips included.
  • The machine chops the work. Say "search 0 to 100000" — it slices the range across boards itself.
  • Survives losing boards. A dead worker's chunk is redone elsewhere; if the brain dies, the machine re-elects.
  • Sandboxed tasks. User programs run as bytecode in a VM with hard time, memory, and output bounds. A bad task dies alone.
  • Deterministic. Same code + same input = same bytes on every chip, so failed chunks re-run anywhere without asking anyone.
  • No cloud, no router. Boards talk point-to-point over ESP-NOW. Your homelab stays your homelab.

Run it in one minute — no hardware needed

Every part of ESPlab is portable C, so a "board" can be a Linux process. The prebuilt tools ship in the release:

tar xzf esplab-host-tools-linux-x64.tar.gz
./vboard --id 01 & ./vboard --id 02 --chip s3 & sleep 6
# in another terminal, from the repo:
python3 tools/webui/webui.py        # dashboard: http://localhost:8080
# then, from any board console:
submit search 0 100000 13           # the machine does the rest

Real boards: same firmware, idf.py flash — flashing guide is in the README.
